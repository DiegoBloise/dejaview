What’s inside

A framework, not a script collection

Java 25 → JavaScript

TeaVM 0.16.0 compiles Java bytecode to a plain app.js at build time. No WebAssembly, no bundler magic — just a script tag.

Implemented

Signals & Computed

Signal, Effect, lazy Computed with push-based invalidation, batching, FIFO scheduling and scope disposal.

Implemented

Reactive renderer

A sealed RenderNode tree with positional reconciliation; the renderer reuses DOM nodes and updates attributes and properties surgically.

Implemented

Component model

Component, AbstractComponent with ResourceRegistry ownership, class-based and functional components via Views.componentFactory.

Implemented

Boring HTML, by design

Plain class and style attributes, untouched by the framework — Bootstrap, Tailwind CSS and daisyUI work without a proprietary pipeline.

Implemented

Tested end to end

JUnit across all modules and Playwright browser tests that click through the compiled counter and showcase examples in Chromium.

Implemented

Philosophy

Three promises, kept in code

Java stays primary

No DSL, no annotation processor magic required to start. The API is plain records, interfaces and generics that compile with --release 25.

Honest status

Every user-facing feature is either covered by automated tests or clearly labelled as planned. The docs never present proposals as shipped capabilities.

No lock-in

dejaview-core never imports a browser API. Renderers, DOM contracts and examples live in separate modules you can replace or extend.

Implementation status

What works today — and what doesn’t yet

As of 0.1.0-SNAPSHOT. The full matrix lives in IMPLEMENTATION_STATUS.md; the ROADMAP is authoritative for what ships next.

Implemented & tested

  • Maven multi-module build, Maven Wrapper, Java 25 baseline
  • Immutable view model (Views.div, h1, button…) and attributes/properties/events
  • Signal, Effect, Computed, batching, FIFO scheduler, ReactiveScope
  • Sealed RenderNode tree with positional reconciliation and reactive DOM updates
  • Component model: Component, AbstractComponent, ResourceRegistry, functional components
  • Plain class/style attributes — Bootstrap, Tailwind CSS, daisyUI markup just works
  • Browser examples (counter, showcase) compiled by TeaVM and verified in Chromium

Planned, not built yet

  • Inputs, outputs, named slots and lifecycle hooks for components (Sprint 08)
  • Fine-grained DOM binding nodes and keyed reconciliation
  • Client-side router, forms, HTTP client, dependency injection
  • SSR/SSG and hydration
  • In-browser compilation for the playground (needs the dev-server milestone)
  • Automated Bootstrap/Tailwind/daisyUI compatibility suite

Architecture

Layered, with the boundary you expect

examples/*counter · showcase — TeaVM-compiled apps
↓
dejaview-domDOM contracts · render tree · reconciler · TeaVM JSO adapter
↓
dejaview-reactivitySignal · Effect · Computed · batching · scopes
↓
dejaview-coreimmutable view model · Component · ResourceRegistry

Dependencies point inward only. dejaview-core has no browser, DOM or TeaVM imports — it compiles and tests on plain JVM 25. The full design lives in ARCHITECTURE.md; significant decisions are recorded in ADRs 0001–0014.

Getting started

From zero to a running counter in minutes

  1. 1 Prerequisites

    JDK 25 and Git. Maven is not required — the repo ships the Maven Wrapper.

  2. 2 Clone & build

    git clone https://github.com/dejaview/dejaview.git
cd dejaview
./mvnw clean verify

  3. 3 Run the counter in a real browser

    Compiles the example with TeaVM and clicks through it in headless Chromium.

    ./mvnw -Pe2e -pl examples/counter -am verify

  4. 4 Serve this website

    Static files, no build step. Serve from the repo root so example bundles resolve.

    python3 -m http.server 8099
# http://localhost:8099/website/
